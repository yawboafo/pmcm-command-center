# 3D assets: equipment, furniture, people, food & branding

The twin's equipment, furniture, **people and food props** are **optimised GLBs generated by a
scripted Blender pipeline** (`blender/`), with the in-browser procedural primitives
(`equipment.tsx`, `furniture.tsx`, `agents.tsx`, `live.tsx`) kept as the fallback.
Storefront and counter branding is canvas artwork in `materials.ts` applied to the
buildings (`building.tsx`) and to the UV'd `LABEL` / `SCREEN` quads of the GLBs (`modelAssets.tsx`).
This page covers what exists, how it's made, what it costs, and what still needs
a human 3D artist.

QA contact sheet: `blender/renders/contact-sheet.png` (one EEVEE render per asset in
`blender/renders/<type>.png`). How to run and extend the pipeline: `blender/README.md`.

## Pipeline

```
src/lib/floorplan/catalog.ts ──(sizes parsed at build time)──┐
                                                             ▼
blender -b --python blender/build_assets.py   equipment + furniture builders in app space (x w, y up, z front)
blender -b --python blender/build_people.py   rigid-part people (one GLB, one node per part) + posed QA line-up
blender -b --python blender/build_props.py    food / packaging / hand-held props (one GLB each)
   │  lib.py: PBR material library, bevelled boxes (harden-normals chamfers), boolean cut-outs,
   │          open pans/wells, swept pipes, lathe (bottles), torus, wire shelves, casters, legs
   │  join parts by role → BODY / STATUS / GLASS / SCREEN / LIGHT / LABEL / FOOD / STOCK / PROPS / DUCT
   ├─► blender/out/raw/<kind>/<type>.glb (+ .lod1.glb)   glTF exporter, Draco off, +Y up
   └─► blender/renders/<type>.png                         EEVEE, neutral studio, 3/4 view
python3 blender/postprocess.py
   ├─► npx @gltf-transform/cli optimize   dedup + weld + prune + meshopt (quantised), no flatten/join/instance
   ├─► public/models/<kind>/<type>.glb (+ .lod1.glb)
   ├─► public/models/manifest.json        triangles / bytes measured from the final files
   └─► blender/renders/contact-sheet.png
```

The full rebuild takes about 15 s in Blender plus about 1 min of gltf-transform, and is deterministic
(seeded RNG for stock and props).

### Contract with the app

* One GLB per type at `public/models/equipment/<type>.glb` / `public/models/furniture/<type>.glb`.
* Metres, +Y up, front facing +Z, modelled at the catalogue default `size`.
* Origin at the footprint's floor-centre; `elevated` types (hood, `walk-in-*` evaporators,
  menu board) use the bottom-centre of the item.
* `BODY` is the main body. `STATUS` is the single-material indicator light the app recolours.
  Optional roles: `GLASS` (alpha-blended panes), `SCREEN` (emissive displays), `LIGHT` (lamps,
  heat lamps, light boxes), `LABEL` (UV'd quad for the app's canvas text), `FOOD` / `STOCK` /
  `PROPS` (vertex-coloured dressing, one draw call, can be hidden), `DUCT` (hood duct stub).
* Live-layer anchors are kept: fryer oil and wells, oven belt heights with an open tunnel and a front
  window so `OvenLive`'s glow is visible, the make-line board and pan rail, hot-holding tray
  heights, rice-warmer wells, dispatch shelf heights, the QC shelf and counter worktops. See `# LIVE:`
  comments in `blender/build_assets.py`.
* Some items rise above the nominal `h` (backsplashes, the make-line's open lid, the packaging
  overshelf, the pickup screen, the hood duct, top-shelf stock). The manifest records the real `bounds`.
  **Scale by `e.size / manifest.size`, not by the bounding box.**

### Loader requirements (for whoever wires the app)

* Files are **meshopt-compressed** and quantised: `extensionsRequired =
  [EXT_meshopt_compression, KHR_mesh_quantization]`. Configure the loader with
  `loader.setMeshoptDecoder(MeshoptDecoder)` from
  `three/examples/jsm/libs/meshopt_decoder.module.js` (or drei `useGLTF(url, false, true)`).
  `python3 blender/postprocess.py --no-optimize` produces uncompressed files if needed.
* Quantisation stores dequantisation in each node's `position`/`scale`, so **do not overwrite
  node transforms**. Place and scale a wrapper group, and recolour `STATUS` via its material.
* Multi-material nodes (typically `BODY`) load as a `Group` named `BODY` with one child mesh per
  material. `STATUS` is always a single `Mesh`.
* Glass uses `alphaMode: BLEND` (no transmission pass). Emissives use `KHR_materials_emissive_strength`.
* Dressing (`FOOD`/`STOCK`/`PROPS`) uses `COLOR_0`; GLTFLoader enables `vertexColors` automatically.
* `LOD1` files exist for the 6 largest equipment types (by catalogue volume). Use them with
  `THREE.LOD` or drei `<Detailed distances={[0, 12]}>`.
* No image textures anywhere. Everything is PBR factors, so no texture memory or KTX2 decoder is needed.
* `LABEL` / `SCREEN` quads keep `TEXCOORD_0` (postprocess runs with `--prune-attributes false`); glTF
  UVs are top-left origin, so canvas textures put on them need `flipY = false` (`forGltf()` in
  `modelAssets.tsx`). The app fills them per type: menu-board screen = menu artwork, POS counter
  front = counter graphic, pickup / dispatch strips, drinks-fridge header, hand-wash sign.

### Pipeline fixes made in this pass (affect every asset)

* **Vertex colours were exported white.** `lib.export_glb` passed `export_image_format="NONE"`, which
  makes Blender's glTF exporter ignore the material's colour-attribute node: it wrote an all-white
  `COLOR_0` and the real colours as `COLOR_1`, which gltf-transform then pruned. All `FOOD` / `STOCK` /
  `PROPS` dressing in the earlier equipment files rendered white in the app. Removed; everything rebuilt.
* **Label UVs were pruned.** Untextured quads lost `TEXCOORD_0` in `optimize`, so any canvas texture
  sampled a single texel. Fixed with `--prune-attributes false` (no size change worth noting).

## People (`build_people.py` → `public/models/characters/people.glb`)

One GLB holding a **shared base body plus swappable parts**, each a separate node whose origin is
its joint (rest pose, 1.72 m adult; the manifest entry carries the rig: joint positions, arm splay,
part → joint map):

| Group | Parts | Tris |
|---|---|---:|
| Body (always) | `head` 440, `pelvis` 144 / `pelvis_skirt` 168, `upper_arm` 128, `forearm` 96, `hand` 108, `thigh` 140, `shin` 96, `foot` 112 (limbs ×2) | |
| Tops | `torso_polo` (staff: collar trim, buttons, name badge) 428, `torso_tee` 280, `torso_shirt` 464, `torso_blouse` 308, `torso_jacket` (rider: stand collar, zip, reflective band) 456 | |
| Head-wear | `hair_short` 126, `hair_afro` 130, `hair_bun` 226, `headwrap` (duku) 306, `cap` 194, `helmet` (visor) 240 | |
| Kit | `apron_bib` 72, `apron_waist` 100, `delivery_box` (insulated, straps, reflective band) 176 | |
| **A person** | tee + trousers + short hair ≈ **2,350 tris**; crew (polo, cap, apron) ≈ 2,860 | 4,990 total, **69 KB** |

**Colour without textures or material variants.** Each vertex stores `COLOR_0.r` = palette slot
/ 15, `.g` = ray-traced ambient occlusion baked in the rest pose (0.5–1), `.b` = roughness override.
Slots 0–7 are per-instance colours (skin, top, bottom, shoes, hair, accent, forearm, shin); 8–15 are
fixed (eyes/soles, white trim, brand red/yellow, visor) or shades. `people.tsx` patches
`MeshStandardMaterial` to decode the slot against two per-instance `vec4` attributes (eight packed
sRGB colours), so outfits (`outfitFor()`: crew by role, supervisor black polo + yellow cap, riders
green / dark jackets with matching boxes and helmet colours, customers' tops, trousers / skirts /
shorts, short / long sleeves, six skin tones, hair styles, head-wraps and caps) cost nothing.

**Rig and draw calls.** The app keeps the per-frame pose logic (walk with knee/elbow bend, carry,
work, clean, sit, idle sway and look-around) but writes the joint matrices straight into **one
`InstancedMesh` per part** (~23 meshes + carried items + blob shadows), so the crowd costs a fixed
~25 draw calls (+ shadow pass) whatever the head-count, versus ~14 per person before. Clicks hit an
invisible instanced capsule per agent. No skinning. Carried items are the prop models (pizza on a
tray, pizza box, tray of breaded chicken, crate and jollof pack held in front; drink / side cup in the
right hand, takeaway bag hanging from it, kept upright).

## Food & props (`build_props.py` → `public/models/props/*.glb`)

Single `BODY` node, shared `vcol` material, origin at the bottom centre, ≤ 600 tris each, 3–7 KB:
`pizza` 440, `pizza-raw` 494, `pizza-tray` (cut) 528, `pizza-box` 92, `pizza-box-open` 496,
`chicken-drum` 132, `chicken-basket` (fryer basket) 544, `chicken-bucket` 590, `chicken-tray`
(breaded) 592, `rice-pack` (open jollof clamshell) 360, `side-cup` (kelewele) 272, `drink-can` 236,
`drink-bottle` 248, `takeaway-bag` 212, `crate` 148 — about 80 KB in all.

Used in `live.tsx` at the old stand-ins' positions and heights: oven belt pizzas (raw model for the
first third of the bake, then browning via a per-slot material tint), fryer baskets (scaled to the
fryer), hot-holding drumsticks (instanced), make-line raw pizza, breaded-chicken trays at the
breading / prep stations, QC-pass items and packing-bench items chosen by the task's unit / order
(pizza box open → closed, bucket, rice pack, bag), and takeaway bags at collection and dispatch
(now standing on the rack's wire shelf instead of 1.5 cm into it). With no props in the manifest, or on
a load error, the procedural primitives come back.

## Storefront & interior branding (`building.tsx`, `materials.ts`)

Text and colour only (no logo artwork): entrance canopy with a lettered fascia
("PIZZAMAN CHICKENMAN", brand font), yellow drip edge, soffit downlights and a "WELCOME" door vinyl;
white / yellow / green brand stripes and a cap flashing on the red fascia; shopfront glazing with
deeper aluminium sections, transom, kick rail and a manifestation band (brand stripes + product
line, also the legally expected glass marking); POS counter fronts with an "ORDER HERE" graphic
(flame streaks, yellow / green swoosh, pizza and chicken illustrations); new menu-board artwork with
drawn pizza, drumsticks, jollof and pack illustrations (no prices, to avoid inventing them); warm
downlights front of house. The scripted menu board now shows this artwork on its `SCREEN` (it was a
blank blue panel) and is no longer forced procedural.

## Performance budget

| Budget | Limit | Actual |
|---|---|---|
| Large equipment (≥ 0.35 m³) | ≤ 6,000 tris | max 5,250 (`drinks-fridge`) |
| Small equipment | ≤ 2,000 tris | max 976 (evaporators) |
| Furniture (many instances) | ≤ 3,000 tris | max 2,664 (`stool-bar`) |
| `public/models/equipment` | ≤ 2.5 MB | **≈ 588 KB** incl. 6 LOD1 files |
| `public/models/furniture` | n/a | ≈ 85 KB |
| Image textures | avoid | none |
| Draw calls per instance | n/a | 2–11 (one per material). Typically fewer than the procedural models, which used one mesh per box |

Rules of thumb for future assets: keep a hero item ≤ 6k tris and ≤ 50 KB compressed, ≤ 10
materials, and put all small coloured dressing on the shared `vcol` material. If draw calls
become the bottleneck in a large branch, the app can share materials across GLBs by name
(they match `M.*`), or merge static equipment per room with `BufferGeometryUtils.mergeGeometries`.

People, props and branding are covered in the sections above (and in `manifest.json`: `kind`
`characters` / `props`).

## What scripted modelling can and cannot do

**Achievable from script (done here):** correctly proportioned hard-surface equipment;
bevelled edges with hardened normals (catching highlights like real folded stainless); real
openings (fryer wells, oven tunnels, sink bowls, pan rails via booleans); PBR metal, enamel,
glass and emissive factors; tubular legs, casters, handles and swing spouts; wire shelving; simple
generic stock (boxes, sacks, tins, bottles via lathe); and deterministic LODs.

**Also done from script now, at "stylised low-poly" quality:** people built from lofted sections
(proportioned body, faces with eyes / brows / nose / ears, clothing variants, AO baked by ray casting),
food and packaging as faceted flat-colour shapes, and branding as canvas lettering.

**Still not achievable from script at production quality:** sculpted / scanned organic shapes,
brand artwork and print graphics, cloth that folds, faces with likeness, believable motion. The
characters read well from the dollhouse and at counter distance, but up close they are clearly
low-poly mannequins with rigid joints (visible at the elbows and knees, no fingers, no cloth
deformation), and the food is flat colour without texture.
